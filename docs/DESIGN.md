# AdminUtil 설계 문서

친구들끼리 쓰는 Paper 서버의 **관리자 도구** 플러그인이다.
옛 `Utility` 플러그인의 `admincommands`(`/ac`)를 중심으로 관리자 기능만 떼어 새로 만든 것이다. 플레이어용 기능은 `SMPUtil`이 맡는다.
코드 규칙은 루트의 `CLAUDE.md`를, 기능 규칙과 결정 이유는 이 문서를 기준으로 한다.

## 1. 범위

**들어가는 것**: 관리자가 서버를 운영하고 테스트하는 데 쓰는 기능. 모든 권한은 기본 OP.

| 분류 | 기능 |
|---|---|
| 관리자 토글 | 비행, 무적, 노데미지, 배고픔 없음, 줍기 차단, 유리 헬멧 |
| 도구 지급 | 관리자 도구 세트, 장미칼 |
| 재미 도구 | 순보, 번개 막대 |
| 투명화 | vanish |
| 열람 | 인벤토리·엔더상자 열람 |
| 채팅 | 서버 전체 채팅 서식 변경 |

**들어가지 않는 것**

- 모든 플레이어용 기능 → `SMPUtil`
- 돈 → `Econet` (동전 집계와 경제 백업은 장부와 묶여 있어야 해서 Econet에 남는다)
- 이 표에 없는 기능을 추가하려면 먼저 이 문서에 범위를 추가한다.

## 2. 명령어

`/ac`(별칭 `/admin`, `/관리`) 아래에 모은다. 옛 `/ac` 사용 습관을 유지하기 위해서다.

| 명령어 | 내용 |
|---|---|
| `/ac fly` | 비행 토글 |
| `/ac invulnerable` | 무적 토글 |
| `/ac nodamage` | 노데미지 토글 |
| `/ac unstarve` | 배고픔 없음 토글 |
| `/ac pickup` | 줍기 차단 토글 |
| `/ac glass` | 유리 헬멧 토글 |
| `/ac list` | 내 토글 상태 보기 |
| `/ac tools [재질]` | 관리자 도구 지급·회수 |
| `/ac knife [players on\|off]` | 장미칼 지급·회수, 플레이어 피해 설정 |
| `/ac shunpo` | 순보 토글 |
| `/ac lightning` | 번개 막대 토글 (옛 `/stick`) |
| `/ac chat [서식\|reset]` | 채팅 서식 보기·변경·초기화 |
| `/vanish` (`/v`, `/투명`) | 투명화 토글 |
| `/ac inv <플레이어>` | 인벤토리 열람 |
| `/ac ender <플레이어>` | 엔더상자 열람 |

- 각 하위 명령어에 권한 `adminutil.<기능>`을 둔다(기본 OP). 옛 코드는 `isOp`만 검사했다.
- 플레이어 인자는 진짜 이름과 SMPUtil 한글 닉네임을 모두 받는다(6장).

## 3. 관리자 토글

### 공통

- **토글 상태는 플레이어 PDC에 저장한다**(`adminutil:<토글 이름>`, BOOLEAN). 재시작·재접속해도 유지된다.
  - 이유: 옛 코드는 전역 리스트에 둬서 재시작하면 풀렸고, 비행 중이던 관리자가 재접속하면 추락할 수 있었다.
- 접속할 때, 리스폰할 때, 게임 모드가 바뀔 때 저장된 토글을 다시 적용한다.
- `/ac list`는 모든 토글의 상태를 보여 준다.

### 각 토글

| 토글 | 동작 |
|---|---|
| fly | 서바이벌에서도 비행 허용. 끄면 비행 해제 |
| invulnerable | 모든 피해 취소. 노데미지와 동시에 켤 수 없다(켜면 다른 쪽이 꺼진다) |
| nodamage | 피해량만 0. 넉백과 피격 효과는 남는다. 켤 때 체력을 가득 채운다 |
| unstarve | 배고픔·포화도를 최대로 유지 |
| pickup | 켜면 아이템과 경험치 구슬을 줍지 않는다 |
| glass | 머리에 유리를 씌운다. 원래 머리 칸 아이템은 인벤토리로 옮기고, 넘치면 발밑. `/clear` 뒤에도 다시 씌운다 |

- 무적 상태에서도 `/kill`은 통하게 한다. 관리자가 스스로를 처리할 방법이 막히면 안 되기 때문이다(옛 `KillBypassListener`).

## 4. 도구 지급

- `/ac tools [wooden|stone|golden|iron|diamond|netherite]`: 삽·괭이·곡괭이·도끼를 핫바 6~9번 칸에 지급한다. 기본 나무(도끼만 돌). 효율 10, 내구 10, 부서지지 않음.
- `/ac knife`: 장미칼(즉사급 피해 검)을 핫바 4번 칸에 지급한다. 기본은 플레이어에게 피해를 주지 않고, `players on`으로 켤 수 있다. 토템 부활도 무시한다.
- 같은 명령어를 다시 치면 회수하고 원래 아이템을 돌려놓는다.

### 결정과 이유

- **지급한 도구는 PDC 태그로 식별한다**(`adminutil:tool`). 표시 이름으로 식별하지 않는다.
  - 이유: 옛 코드는 이름에 "장미칼"이 들어 있으면 즉사 효과를 줬다. 아무 검이나 모루로 "장미칼"이라고 이름 붙이면 누구나 즉사 검을 가질 수 있었다.
- **도구 때문에 밀려난 원래 아이템은 플레이어 PDC에 직렬화해 저장한다**(`ItemStack.serializeAsBytes`).
  - 이유: 옛 코드는 메모리에만 백업해서, 도구를 든 채로 서버가 재시작하면 원래 아이템이 사라졌다.
- 회수할 때는 태그가 붙은 아이템을 인벤토리 전체에서 지운다(다른 칸으로 옮겨 놨어도 회수).
- 관리자 도구가 다른 사람 손에 들어가지 않도록, 태그가 붙은 도구는 떨굴 수 없고 상자에 넣을 수 없으며 죽어도 떨어지지 않는다.

## 5. 재미 도구

- **순보**(`/ac shunpo`): 켜면 검을 들고 우클릭할 때 15블록 안에서 바라보는 플레이어의 등 뒤로 순간이동한다.
- **번개 막대**(`/ac lightning`): 켜면 막대기를 핫바 3번 칸에 지급하고(도구·장미칼 칸과 겹치지 않게), 들고 우클릭하면 바라보는 블록에 번개를 떨어뜨린다. 막대기는 4장 도구와 같은 방식(PDC 태그, 밀려난 아이템 저장)으로 다룬다.
  - 옛 `/stick`은 아무 막대기에나 반응했다. 태그가 붙은 막대기에만 반응한다.

## 6. 플레이어 찾기와 SMPUtil 닉네임

관리자 명령어의 플레이어 인자는 진짜 이름과 SMPUtil의 한글 닉네임을 모두 받는다.

- **SMPUtil을 코드로 의존하지 않는다.** SMPUtil이 플레이어 PDC에 저장한 닉네임을 데이터로 읽는다. SMPUtil이 없으면 닉네임이 없을 뿐이고 진짜 이름으로만 찾는다.
- 접속 중: `player.persistentDataContainer`에서 읽는다.
- 오프라인: 7장에서 읽는 플레이어 데이터 파일의 PDC 영역에서 읽는다. Bukkit은 PDC를 플레이어 NBT의 `BukkitValues` compound에 저장하는 것으로 알려져 있으나, Paper 26.3에서 실제 키 위치를 확인하고 이 문서에 적는다.

### 다른 플러그인과의 약속 (변경 금지)

SMPUtil DESIGN.md 3장의 표와 같아야 한다.

| 항목 | 값 |
|---|---|
| 키 | `smputil:nickname` (`NamespacedKey("smputil", "nickname")`) |
| 타입 | `PersistentDataType.STRING` |
| 없음 | 키가 없으면 닉네임이 없는 것(진짜 이름 사용) |

## 7. 인벤토리·엔더상자 열람

- **접속 중인 플레이어**: 실제 인벤토리·엔더상자를 관리자 화면에 연다. 실시간이고 수정할 수 있다.
- **오프라인 플레이어**: 플레이어 데이터 파일을 읽어 **읽기 전용** 사본을 연다. 모든 클릭·드래그를 취소한다.

### 결정과 이유

- **오프라인 편집은 하지 않는다.**
  - 이유: 옛 코드는 오프라인 엔더상자 편집 결과를 별도 파일에 두었다가 접속할 때 덮어썼다. 그 사이에 서버가 그 플레이어 파일을 따로 저장하거나 백업을 되돌리면 아이템이 사라지거나 복제된다. 파일을 직접 고쳐도, 해당 플레이어가 접속하는 순간 서버가 덮어써서 수정이 사라질 수 있다.
- 오프라인 파일 읽기는 Econet이 이미 구현하고 실제 서버로 확인한 방식을 따른다(Econet 저장소 `paper/.../admin/Nbt.kt`, `PlayerDataFile.kt`, Econet CLAUDE.md "관리자 도구").
  - Paper 26.3의 위치는 `<월드 루트>/players/data/<uuid>.dat`. 옛 `playerdata/`는 대체 경로로만 본다.
  - `World.getWorldFolder()`가 차원 폴더를 돌려주므로, 월드 루트는 `level.dat`가 있는 폴더까지 올라가 찾는다.
  - NMS 없이 NBT를 직접 읽고, 아이템 변환만 `ItemStack.deserializeBytes`에 맡긴다.
  - 코드는 복사해 와도 된다. 두 플러그인이 서로 의존하지 않는 게 공유 라이브러리를 두는 것보다 중요하다.
- 인벤토리 화면에는 갑옷·왼손 칸도 함께 보여 준다.

## 8. 투명화 (vanish)

- 켜면 투명화되지 않은 모든 플레이어에게서 숨긴다(`hidePlayer`). 탭 목록에서도 빠진다.
- 투명화된 관리자끼리는 서로 보인다.
- 투명화 중에는 액션바에 "투명화 상태"를 계속 표시한다.
- 알림 방식(설정, 관리자별로 바꿀 수 있음):
  - 가짜 퇴장·입장 메시지를 띄운다
  - "[Vanish] 누구 투명화"라고 그대로 알린다
  - 아무에게도 알리지 않는다(본인에게만)
- 투명화 상태는 PDC에 저장한다. 투명화 상태로 접속하면 입장 메시지를 숨기고 바로 숨긴다.
- 투명화된 플레이어는 아이템을 줍지 않고, 몹이 쫓지 않는다.
- SMPUtil은 `canSee`로 투명화된 플레이어를 접속자 목록·자동완성·텔레포트 대상에서 뺀다. 별도 연동 코드는 필요 없다.

## 8-1. 채팅 서식

- `/ac chat <서식>`으로 서버 전체 채팅 서식을 바꾼다. 기본값은 `&e<nick>&r: <msg>`. `/ac chat reset`은 기본값, 인자 없이 치면 현재 서식을 보여 준다.
- 쓸 수 있는 것: `&` 색 코드, `<nick>`(SMPUtil 닉네임, 없으면 진짜 이름), `<name>`(진짜 이름), `<msg>`(내용). `<msg>`가 없는 서식은 받지 않는다.
- 서식은 `plugins/AdminUtil/chat-format.yml`에 저장해 재시작해도 남는다. 파일 값이 틀리면 시작 시 실패한다.
- 닉네임은 6장과 같은 PDC 약속(`smputil:nickname`)으로 읽는다. SMPUtil을 코드로 의존하지 않는다.
- **색 코드는 서식에서만 해석한다. 플레이어가 친 내용은 그대로 둔다.**
  - 이유: 내용까지 해석하면 일반 플레이어가 `&c`로 관리자처럼 꾸미거나 서식을 흉내 낼 수 있다.
- 서식은 서버 전체에 하나다(플레이어별 서식은 범위 밖).

## 9. 외부 플러그인 연동 원칙

나중에 WorldEdit 등과 연동할 때를 위한 원칙이다. 지금은 구현할 것이 없다.

- 외부 플러그인 연동은 **선택 기능**이다. 그 플러그인이 없으면 해당 기능만 꺼지고 나머지는 동작한다.
- `plugin.yml`에 `softdepend`로 선언하고, 의존성은 `compileOnly`.
- 외부 플러그인의 클래스를 쓰는 코드는 별도 클래스에 몰아 두고, `isPluginEnabled`로 확인한 뒤에만 그 클래스를 만든다.
  - 이유: 확인 없이 로드하면 그 플러그인이 없는 서버에서 `NoClassDefFoundError`로 AdminUtil 전체가 죽는다.
